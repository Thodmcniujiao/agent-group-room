# 0.14.0 协作日志与聊天头像大小

2026-10-22。已实现并部署本机 49315 服务；生产服务健康版本为 0.14.0。本轮没有调用真实模型生成答复。

## 使用

- 输入框上方“本地 log”默认开启，按房间保存。开启后，每次协作、自由讨论、批准续接或复查建立独立记录，关联发言、成员、角色、会话分支与逐次请求。运行中切换影响后续诊断数据；关闭保留已有文件，重新开启属于部分记录。
- 点击“协作日志”选择协作记录，查看逐次发言的用量、缓存比例、上下文及软预算峰值；点击发言查看原文并下载 JSONL。“协作消息与事件”提供该次协作的真实用户消息、成员消息与宿主事件。
- “Agent 管理 → 设置所有头像 → 聊天框头像大小”：24–96 px，拖动预览、松开自动保存，提供恢复 32 px 按钮；应用于全部协作室的聊天头像，侧栏和头像图片维持原设置。

## 日志范围与格式

实际目录为本机状态目录下的 `gui/collaboration-logs/<room_id>/<run_id>/`，与项目文件分开。每次协作包含 `manifest.json`、`events.jsonl` 及按发言 ID 命名的 JSONL。日志时间为 UTC，选择器以 Europe/London 显示。历史未采集的请求不会补造；尚未调用模型的协作室显示无日志。

JSONL 记录包含 `schema_version`、`time`、`room_id`、`run_id`、`call_id`、`event` 和 `data`。发言清单保留成员、角色、阶段、请求型号、会话键、分支、状态、耗时及用量汇总。

- `host_input`：宿主实际组装并交给适配器的提示、角色指令、工具定义和群消息关联。
- `http_request`：实际 HTTP 发送边界取得的请求体。`body` 为可读 JSON，`body_base64` 保留原始请求体字节；`request_ref` 与用量记录关联。地址去除鉴权用户信息和查询部分，采集器不转储鉴权请求头或整份进程环境。
- `http_response_started` / `http_response_bytes`：HTTP 状态、内容编码及按顺序保存的返回字节。按同一 `request_ref` 拼接 Base64 解码后的字节，可恢复原始返回正文；如有压缩，再按 `content_encoding` 解码。未完成流保留已经收到的部分。
- `cli_process` / `cli_stdin` / `cli_stdout` / `cli_stderr`：实际 CLI 调用参数、宿主发出的提示及协议消息、CLI 返回事件和 stderr 字节。Claude MCP 配置只包含宿主显式传入的本地会话变量，未转储完整进程环境。
- `usage`：服务端原始用量和归一化计量。`call_finished` 保留真实答复或失败、取消前收到的部分输出，以及对应群消息 ID。

CLI 的 `capture_scope=cli_host_boundary`，并标记 `internal_cli_payload_available=false`：CLI 内部自动拼入的系统提示、私有历史和最终服务商请求体，如果 CLI 没有暴露，就不能声称已经完整采集。API 请求记录为 `api_http_body`。宿主的额外执行器子进程通过独立缓冲文件回传实际 HTTP 数据，退出后清理缓冲；不扩大工具或执行权限。

开关控制新增诊断日志。原有群聊、私有会话续接文件、用量账本等按原逻辑持久化；关闭 log 不删除这些资料。日志写入失败通过界面事件提示，协作继续。原始日志含实际任务资料，不进入公开验收导出。

## 计量口径

输入总量包含缓存读写，输出总量包含推理；不将子项再次加入总数。缺失字段保持未知，部分已知的汇总另标未知请求。缓存命中率仅使用输入与缓存读取均已知的记录计算。

Codex 累计计数取差值；计算当前上下文占用时取 `last.inputTokens`，不拿累计输入充当当前上下文。上下文窗口优先使用返回的 `modelContextWindow` 或 Claude `modelUsage.contextWindow`，缺失时使用宿主保守估算并显示“窗口估算”。上下文窗口占用与本地软预算占用分开显示。CLI 的计量条数只表示可辨识的返回记录，不能宣称等于其内部全部 API 请求数。

- [接口验证](verification.json)：13 组检查通过；协作消息分 46 页恢复原始 UTF-8 字节和哈希；跨房间、无效 ID 和越界分页被拒绝；下载使用 no-store；显示设置拒绝无 CSRF 或无效类型的修改，头像图片未被改动。
- [界面验证](ui-verification.json)：日志默认开启、关闭刷新后保留、原文查看和下载、明暗主题、420 px 窄窗口；头像 24/32/64/96 px、恢复默认、刷新持久化、聊天宽度变化及侧栏宽度保持已检查。
- 新界面的可访问性扫描为 0 个确定违规；关闭符号的对比度仍需人工判断，已视觉检查。日志原文和表格都支持键盘滚动。详见本目录 `*-a11y*.json` 与 PNG。
- [本机部署](deployment.json)：空闲时备份数据库并切换；源码哈希与最终验收一致。部署前后均为 6 个协作室、152 条消息、1 个方案、3 条批准、27 条用量记录，原房间配置哈希未变。六个房间的新日志默认开启；没有伪造历史日志，生产初始新日志数为 0。生产头像大小维持默认 32 px。

早期回归因注入 HTTP 客户端的方式与既有适配器测试冲突而失败，已改为给适配器实际使用的客户端追加传输观察器；修复记录保留于 `integration-1/`、`integration-2/`。首次下载校验器按大小写读取响应头产生误判，改用大小写无关的实际头校验后通过。浏览器在夹具服务重启尚未就绪时出现一次加载失败，服务健康后重开成功；窄窗口下侧栏控件不可点击时，恢复桌面宽度继续检查。

原始 API 数据使用本地 HTTP 模拟服务；提供商子进程和 MCP 进程是真实本机调用，CLI 会话输出用协议夹具验证。真实服务商生成与 CLI 内部隐藏请求未在本轮付费调用测试。最终运行时行为仍以各服务实际返回字段为准。
