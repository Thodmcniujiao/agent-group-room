# 余额缓存与讨论上限验证 · 2026-10-26

## 实现

- Google 同账号成功读数超过 10 分钟后标为缓存，查询失败时继续使用；超过 30 分钟在应用中持续提醒。部分账单行按 ID 合并，未确认的旧行保留原时间。新确认的零余额、适用范围变化、失效状态及赠金实际到期仍生效。
- 其他账户读数按连接指纹保留上次成功结果并持久保存。失败不清空缓存、不将未知当作零，也不更新成功时间；切换密钥不会复用别的账户数据。
- 完全没有可用缓存、Google 连接核验失败等宿主前置问题暂停等待，不作为监工安排错误反复纠正。未完成监工请求的轮数会撤回；真实完成的安排仍如实计数。
- 达到讨论容忍度上限后，宿主依据实际评审完成顺序定位最后明确反对的在场成员，强制其提交包含目标、实施、验收、风险与未决项的完整方案，原文入新版本后直接生成审批文档。
- 不开启额外争论、不自动批准。无明确反对记录时现有方案直接送审；作者连接失败时暂停。重启可复用已完成的最终回复；用户拒绝后可由同一成员修改并再次送审。

## 验证结果

完整离线回归见 `unit-tests.json`：304 项，302 通过、2 跳过，0 失败、0 错误。新增 18 项用例覆盖缓存失败、重启、时间边界、账号隔离、部分加载、实际到期和零余额、零监工调用等待、同步后续接、并行完成顺序、明确自然语言反对与引用排除、最后反对者直送审批、失败重试及用户拒绝后的新版本。

使用两个独立本机浏览器夹具验证：缓存时间与持续提醒可见，重新同步后提醒消失；达到上限后审批文档的原文作者为最后反对者 Claude，新版为 P1@2，页面等待真实用户批准。未点击批准按钮，未调用真实模型。

部署前确认运行服务没有活动任务，并迁移保留了 3 份上次成功的账户读数；更新后服务健康、提醒控件及新规则帮助文本可读，实际账户缓存继续可见。只读模型目录和账户元数据查询不算模型推理测试。

缓存为历史读数，不会推断真实实时余额；账单抵扣延迟与后续消耗仍可能使其不同于实际资金。当前实现保留原有项目绑定、账号权限和赠金有效性核验。
