## 基础功能验收范围

- 计量继续使用包含缓存的输入总量；缓存读写与推理不重复相加。缺失字段保持未知，观察计数不再混入 token 分项求和。API 前缀记录仅描述宿主 payload 连续性，不宣称等于服务商缓存命中。
- 摘要只从讨论成员的实际完整回复中严格提取，绑定原文哈希；缺失、超长、引用示例和代码围栏不触发补问。格式表态继续使用原文；矛盾摘要在消息卡片提示。
- 目录连同编号、哈希和续页信息共同受预算与条数约束。只有真正发送的摘要才进入覆盖记录；读取一段不算读完整篇。交接包只含摘要时仍实际发出，避免产生虚假投递记录。
- 当前方案、用户原话、相关未决异议保留原文；必要原文放不下时触发预算处理，不静默变成摘要。已投递历史保持原样，普通续轮不会反复追加同一摘要。
- 实际 Bash 子进程在上游 50,000 字符截断之前归档；Git 工具在 40,000 字符截断之前归档；宿主验收保留 30,000 字节之后的末尾错误。真实退出码 3 的验收不会被预览改成成功。
- 输出预览采用明确标记的首尾片段，不宣称保留所有中间诊断。Bash 每个输出流最多捕获 8,000,000 字节，超出时归档标记捕获不完整；宿主验收仍保留超大输出停止边界。`capture_complete=false` 不能被当作完整证据。
- 输出回取按房间与执行会话核验。真实 MCP 进程中，执行者只暴露 `output_read`；讨论成员可使用获准的目录与只读项目工具。项目读取拒绝越界、凭据及控制目录，返回量有界。
- 关闭优化后仍保留已有归档的回取能力。同一执行身份可读取此前执行分支的输出；身份从讨论成员改为执行者时，不会因此获得讨论阶段的输出。两条专门回归覆盖这两个边界。
- 开关按房间持久保存，部分更新保留其他选项。新开关在下次调用应用，已进行中的调用保持原设置；变化后的调用建立新上下文分支。

## 部署与回退

部署前确认 6 个现有协作室均无运行、暂停或排队任务，检查最终验收源码哈希未变化，并创建宿主数据库备份。切换后健康接口返回 `0.13.0`、`active_workflows=0`，数据库完整性检查为 `ok`。

部署前后均为 6 个房间、152 条消息、1 个方案版本、3 条批准、27 条用量记录；房间配置哈希相同。现有房间没有被自动开启优化。六个现有房间的伦敦日期报表均可读取。

使用时刷新桌面窗口，打开顶部“上下文设置”，开启“此房间的上下文优化”，再选择摘要、输出预览、只读项目工具和简洁指令。关闭总开关后未来调用回到原组包策略，历史、归档及既有输出的回取能力保留。

备份位于宿主状态目录 `gui/backups/`，具体文件名见部署记录。数据库备份用于故障恢复；恢复时应先保留部署之后新增的记录。

## 复验入口

```powershell
.\.venv\Scripts\python.exe scripts/run_context_checks.py --report-dir test-reports/summary-roadmap-2026-10-22/rerun
.\.venv\Scripts\python.exe scripts/usage_report.py --by day --json
```

隔离界面服务使用 `scripts/serve_summary_fixture.py --state <新的空目录> --port 49342`，另一个终端运行 `scripts/accept_summary_routes.py --state <同一目录> --report <报告文件>`。夹具服务使用独立数据库与空白连接配置，不读取真实密钥，不发起模型调用。

Windows 日期分组新增依赖 [tzdata 2026.5 官方发行](https://pypi.org/project/tzdata/2026.5/)，wheel SHA-256 在安装前与官方记录核对，版本与哈希记录于 `sources.lock.json`，许可原文保留于 `third_party/licenses/tzdata/`。`pip check` 通过。

可用 `scripts/export_test_reports.py` 导出公开验收白名单；`ui-state*` 夹具目录、数据库和私有会话不进入导出包。
