## 验证结果

最终结果见 [final/unit-tests.json](final/unit-tests.json) 与 [完整日志](final/unit-tests.log)：**178 项，176 通过、2 跳过，0 失败、0 错误**，并保存本次源码 SHA-256 清单。跳过项仍是缺少真实 dubious-ownership Git 仓库夹具的两项，未计为通过。集成阶段的失败和修复保留在 `integration-1`、`integration-2`，中间发布回归另存 `release`。所有普通回归均不调用模型；回归脚本现在强制使用临时 GUI 数据目录，避免导入服务时触及真实协作室数据库。

新增测试覆盖实际路由和预算门，而非仅比较估算函数输出，包括：

- 临时目录/PID/时间变化的阻断去重；错误码区分。
- scope 恢复后先续接精确原契约，再让监工检查执行结果；原失败记录仍为 failed。
- 复查与批准的独立动作来源、CSRF、过期版本、无合成用户消息。
- 长宿主原文部分投递、未读缺口、按剩余 offset 读完后的覆盖。
- 第 19/20 个准确样本前后，CLI/API 的实际预算门结果变化；真实 API 发送路径使用校准。
- 嵌套补丁重建、未变字段不重发、执行者完整交接及契约仅一次。
- 错误作者的反对票拒绝、无共识结束拒绝、真实用户决定仍有效。
- 白名单导出不包含原生历史或未知 JSON。

### Claude 快照核实

[官方 CLI 文档](https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations) 说明，开启快照后原生会话复用首个系统提示直到压缩，压缩后按当前启动配置重建。因此生产入口保留相同的 append 配置，显式开快照；这不会把每次启动的配置追加为多条群消息，也避免压缩后丢失自定义系统约束。

[真实探针结果](claude-snapshot/result.json) 为首轮失败：CLI 返回 `You've hit your weekly limit`，记录用量均为 0；未重试、未降低强度，也没有把它记为快照行为通过。文档和本机参数验证不能冒充真实两轮请求验证。该账户恢复额度后，可显式运行：

```powershell
.venv\Scripts\python.exe scripts/verify_claude_snapshot.py --live
```

这是两次只读模型请求，会使用 Claude 账户额度；它也不是完整任务节省实验。
