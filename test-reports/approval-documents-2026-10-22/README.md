# 正式审批文档与批准续接修复 · 0.12.2

用户要求：待审批方案由宿主生成正式文档；修复批准时持续提示“同一项目已有执行任务”。

## 最终行为

- 宿主从方案库生成不可改写的审批文档快照，记录方案版本、原文作者、项目、成员意见、合作规则及两个 SHA-256。方案正文原样引用，生成文档不调用模型。
- 群聊只增加文档卡片，打开独立阅读窗口查看完整文档；支持 HTML、Markdown 下载，以及浏览器打印/存为 PDF。文档左对齐、15px 正文、A4 打印样式；已检查深浅色窗口和横向溢出。
- 批准绑定文档 ID、文档哈希和方案版本；过期、篡改或合作规则改变时拒绝。真实按钮动作作为来源，不伪造用户消息。
- 旧版待审批消息在读取和历史事件回放时均投影为文档卡片，避免回放把旧的大段小字重新盖回来。原始归档不改写。
- 已结束或缺失的任务不再保留项目锁；尚未开始就取消的任务也释放预留。
- 同项目确有另一任务运行时，批准立即留档并排队，项目空闲后自动继续。取消排队不取消当前项目拥有者，不会并行派发两个工作流。
