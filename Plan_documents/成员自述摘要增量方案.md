## 核心设计哲学：直接引用上游生态，拒绝重写底层算法（Zero Re-implementation）

> [!IMPORTANT] 核心原则变更
> 为什么绝不自己在宿主里写正则与自制算法去模仿开源项目？
> 1. **代码语义极度脆弱**：手写正则过滤日志、裁剪 `git diff` 或提取 AST 符号，极易造成代码语法树断裂、逃逸报错漏截以及不可逆的数据损坏。
> 2. **前缀缓存（Prompt Cache）高度敏感**：主流云端模型对 Prompt Cache 前缀要求逐字节精准对齐，手写动态过滤非常容易破坏哈希一致性，导致不仅没省钱，反而损失 80%–90% 的缓存折扣。
> 3. **训练成果不可替代**：CoMem 的专用 Qwen3-4B 核心价值在于其经过强化学习（GRPO）“行动一致性”对齐的权重模型，绝不是靠宿主写几句提示词就能复现的；Context Mode 的确定性沙箱是多语言底层隔离运行时，不能退化为单行 Python 脚本。
> 4. **宿主唯一定位是胶水层（Thin Glue Layer）**：宿主负责角色权限隔离、共识状态机和调用链路由；所有通用的输出压缩、沙箱隔离、代码拓扑、记忆向量化与账单计量，**全部直接引用官方包、MCP 协议或守护进程**。

## 第一部分：业务层固有逻辑——成员自述摘要（S1–S3）

此部分属于 `Agent Group Room` 房间特有的多 Agent 协作业务逻辑（立场、投票、表态行隔离、交接包），不依赖外部通用工具，由宿主直接实现。

### 范围

摘要只用于“了解大意、决定要不要读全文”的场合；需要核对细节、结论或授权的场合一律用原文。何时用摘要由宿主按下表决定，不由模型决定。

| 场合 | 用什么 | 理由 | 机制特征 |
| --- | --- | --- | --- |
| U1 监工看较早轮次的成员发言 | 摘要 + 编号 | 监工只需要进展脉络；本轮新回复仍给全文 | 外部替换（零主模型开销） |
| U2 未加载消息清单 | 编号 + 作者 + 摘要 | 现在只有编号，读者无法判断是否补读 | 结构化清单（低占用） |
| U3 换监工、会话轮换的交接包 | 近期原文 + 更早的摘要 | 不重放全群也能保留脉络 | 状态压缩包（保护前缀） |
| U4 新加入成员补看历史 | 当前方案全文 + 其余摘要 | 可按需补读全文 | 增量补课包 |
| 成员评审他人方案、提出异议 | 原文 | 用户政策要求成员间原文直接共享 | 保持证据完整 |
| 表态与共识 | B6 格式行 | 摘要可能把“基本同意但……”写成同意 | 严格防幻觉 |
| 执行证据、测试结果、用户批准 | 原文与真实记录 | 摘要不是证据 | 严格防伪造 |
| 执行者 | 只收契约 | 不接触群聊，也不接触摘要 | 角色严格隔离 |

摘要标为“作者自述摘要”，不能作为批准、表态或证据被引用；监工自己的发言不生成摘要（其状态已由账本承载）。

### S1 生成与存储

只要求讨论成员写摘要（监工、执行者不写）；短回复本身就是摘要，不要求额外一行。原文按模型输出原样保存，摘要是从原文里解析出的副本。

```python
# supervision.py / orchestrator.py：讨论成员每次发言的指令末尾追加（长回复才需要）
SUMMARY_RULE = ('如果你的回复超过 {min_chars} 字，在正文后单独写一行摘要，不超过 {max_chars} 字：\n'
                '摘要：立场=<支持/反对/有条件/中立>｜要点=<最重要的一两点>｜未决=<仍未解决的问题，没有写无>\n'
                '表态轮里，摘要行放在表态行之前，表态行仍是最后一行。')

# store.py：messages 增加两列（旧消息为 NULL，不回填）
# ALTER TABLE messages ADD COLUMN summary TEXT;
# ALTER TABLE messages ADD COLUMN summary_source TEXT;   # self | reask | short | none

# orchestrator.py：成员答复发布为 complete 之后
SUMMARY_LINE = re.compile(r'^摘要：立场=(?P<stance>[^｜]+)｜要点=(?P<points>[^｜]+)｜未决=(?P<open>.+)$', re.M)

async def attach_summary(mid, agent, text, settings):
    s = settings['summary']
    if not s['enabled'] or role_of(agent) != 'discussion':
        return
    if len(text) <= s['min_chars']:
        return store.set_summary(mid, text, 'short')          # 短回复：全文即摘要
    m = last_match(SUMMARY_LINE, text)
    if m and len(m.group(0)) <= s['max_chars'] + 8:
        return store.set_summary(mid, normalize(m), 'self')
    if s['reask']:                                            # 缺失或超长：只追问一次
        extra = await reply(agent, '请只补一行摘要，格式：摘要：立场=…｜要点=…｜未决=…',
                            phase='补充摘要', publish=False)     # 不作为新群消息发布
        m = last_match(SUMMARY_LINE, extra)
        if m:
            return store.set_summary(mid, normalize(m), 'reask')
    store.set_summary(mid, None, 'none')

def normalize(m):
    return f"立场={m['stance'].strip()}｜要点={m['points'].strip()}｜未决={m['open'].strip()}"
```

### S2 使用：四个场合的组包

四个场合共用一个“摘要条目”形式；只收到摘要的消息另记为 digested，不计入 delivered，不会被当成“全文已投递”。预算不足时的优先顺序是：本轮必须的全文 → 摘要条目 → 只列编号。

```python
# context.py：统一的摘要条目
def digest_entry(m, settings):
    if m.summary:
        body, kind = m.summary, '作者自述摘要'
    elif len(m.text) <= settings['summary']['fallback_full_chars']:   # 短消息直接给原文
        body, kind = m.text, '原文（较短）'
    else:
        body, kind = None, '无摘要，需要时按编号读取'
    return {'id': m.id, 'seq': m.seq, 'provider': m.provider, 'phase': m.phase,
            'characters': len(m.text), 'summary': body, 'summary_kind': kind}

def pack_digests(entries, budget):        # 超预算时保留较新的摘要，其余只留编号
    kept, ids_only = take_newest_within(entries, budget)
    return kept + [{'id': e['id'], 'seq': e['seq'], 'provider': e['provider']} for e in ids_only]

# U1：监工（主方案 C1 的 state 模式）
def supervisor_originals(turn, pool, state):
    full = [m for m in pool if m.provider == 'you'                 # 用户消息
            or m.status == 'host_error'                             # 宿主错误
            or answers_last_ask(m, state)]                         # 本轮新回复
    older = [m for m in pool if m not in full and is_discussion(m.provider)]
    digests = pack_digests([digest_entry(m, settings) for m in older], turn.digest_budget)
    turn.state['digested'] |= seqs(older)                           # 只给了摘要，不计入 delivered
    return {'messages': full, 'earlier_digest': digests}

# U2：未加载清单（主方案 C2）
prompt.not_loaded = pack_digests(
    [digest_entry(m, settings) for m in omitted] +
    [digest_entry(store.message_by_seq(rid, s), settings) for s in state.gaps],
    turn.digest_budget)

# U3：交接包（主方案 D1）
def build_handoff(role, wf, old):
    recent = last_originals(settings['context']['handoff_recent'])             # 近期仍给原文
    older = [m for m in originals_before(recent) if is_discussion(m.provider)]
    pkg = ...                                                                  # 主方案原有内容不变
    pkg.digest = pack_digests([digest_entry(m, settings) for m in older], digest_budget)
    pkg.included_seqs, pkg.digested_seqs = seqs(recent), seqs(older)
    return pkg

# U4：新加入（或新分支）的讨论成员补看历史
if turn.role == 'discussion' and turn.state['delivered'].empty() and store.boundary(rid) > 0:
    head = full_plan(current_plan_ref(wf))
    recent = last_originals(settings['context']['handoff_recent'])
    digest = pack_digests([digest_entry(m, settings) for m in originals_before(recent)], turn.digest_budget)
```

### I1: 直接接入 Headroom 代理（`headroomlabs-ai/headroom`）

#### 解决痛点
工具大输出、日志、JSON 与 RAG 片段在进入主模型前未经专业优化；手写正则极易发生截断错误或破坏 Prompt 缓存。

#### 直接集成方案
在宿主底层拉起 Headroom 官方代理（或作为进程内中继）：
```bash
# 安装与启动官方代理（只需一行命令）
npm install -g @headroomlabs/headroom  # 或 pip install headroom-ai
headroom proxy --port 8787 --host 127.0.0.1
```

#### 宿主胶水对接（`api_protocol.py` / `provider_sessions.py`）
宿主只做一行网络重定向，**绝不手写任何压缩正则**：

```python
# provider_sessions.py：宿主胶水层
def configure_provider_client(provider_name, api_key, original_base_url):
    """
    如果启用了 headroom_proxy，所有对 OpenAI / Anthropic / DeepSeek 的 API 调用
    统一将 base_url 路由至本地 Headroom 代理中继。
    """
    settings = get_room_settings()
    if settings.get("headroom_proxy_enabled", True):
        # Headroom 代理会自动在上游进行 Live-zone 压缩、CCR 可恢复哈希注入与前缀对齐
        return Client(
            base_url="http://127.0.0.1:8787/v1",
            api_key=api_key,
            default_headers={
                "X-Headroom-Target-URL": original_base_url,
                "X-Headroom-Compression-Mode": "smart-ccr"
            }
        )
    return Client(base_url=original_base_url, api_key=api_key)
```

#### 获得的专业能力（来自 Headroom 原生提供）
1. **Live-Zone 增量压缩**：只对最新进来的 Tool Output 和消息进行压缩，历史对话字节严格不动，**100% 保护云端 Prompt Cache 命中率**。
2. **CCR 可恢复检索（Content-Consistent Retrieval）**：Headroom 在压缩时自动生成哈希面包屑；若下游大模型需要追溯完整细节，Headroom 会自动暴露 MCP 检索工具供其按需回取，无需宿主自制 `output_archive.py`。
3. **结构化 JSON 与日志折叠**：自动分析堆栈与表格，单次工具调用输出通常减少 60%–95%。

### I2: 直接接入 Context Mode 沙箱（`mksglu/context-mode`）

#### 解决痛点
执行者盲目调用 `cat large.log`、`grep -r` 或大范围拉取文件，导致数万 Token 瞬间冲死上下文。手写 Python 子进程包装容易出现跨平台兼容与路径转义问题。

#### 直接集成方案
直接通过 Model Context Protocol (MCP) 将 Context Mode 作为标准沙箱工具服务器接入：
```bash
# 宿主环境安装官方 Context Mode MCP 服务
npm install -g @context-mode/mcp
```

#### 宿主胶水对接（`execution_context.py` / `room_tools.py`）
在 MCP 客户端配置中直接挂载 Context Mode，让执行者使用 Context Mode 原生的确定性沙箱命令：

```python
# room_tools.py：注册 Context Mode MCP 服务
CONTEXT_MODE_MCP_CONFIG = {
    "command": "npx",
    "args": ["-y", "@context-mode/mcp"],
    "env": {
        "CONTEXT_MODE_MAX_OUTPUT_TOKENS": "1500",
        "CONTEXT_MODE_ENABLE_FTS5": "true"
    }
}

async def init_sandboxed_tools(session):
    """
    直接连接 Context Mode 官方 MCP 服务器。
    其内部通过 SQLite FTS5 + BM25 算法在本地完成大输出裁剪与结构化过滤，
    对外暴露经过安全加固的沙箱工具：sandbox_bash, sandbox_read, sandbox_search。
    """
    mcp_client = await connect_mcp(CONTEXT_MODE_MCP_CONFIG)
    # 将其提供的沙箱工具直接绑定到执行者上下文，取代无保护的原生 Bash
    session.register_dynamic_tools(await mcp_client.list_tools())
```

#### 获得的专业能力（来自 Context Mode 原生提供）
- 自动检测超大文件和日志，内部执行确定性切片、错误聚合与统计，Token 占用削减可达 **98%**；
- 会话连续性追踪：自动将文件修改状态保存在本地 SQLite 中，即使主模型轮换也能无缝恢复状态。

### I3: 直接接入 CoMem 专用小模型（`horizon-llm/CoMem` + RTX 5090）

#### 解决痛点
通用 1B/3B 小模型做自然语言总结容易丢失代码行号与关键约束；而云端大模型做总结不仅费用昂贵，还会阻塞主流程。

#### 直接集成方案
在本地 **RTX 5090（32GB 显存）** 上直接加载官方 `horizon-llm/CoMem` 发布的专用模型权重（基于 Qwen3-4B，经过 GRPO 行动一致性训练）。
```bash
# 在本地 vLLM / llama.cpp / Ollama 部署官方 CoMem-Qwen3-4B
ollama run horizon-llm/comem-qwen3-4b  # 或使用 vLLM 拉起 OpenAI 兼容接口
python -m vllm.entrypoints.openai.api_server \
    --model horizon-llm/CoMem-Qwen3-4B-ICML2026 \
    --port 11434 \
    --gpu-memory-utilization 0.25 \
    --max-model-len 32768
```

#### 宿主胶水对接（`context.py`）
直接调用官方 CoMem 推理接口或使用其 $k$-step-off 异步流水线：

```python
# context.py：端侧 CoMem 专用记忆流水线
from openai import AsyncOpenAI

comem_client = AsyncOpenAI(base_url="http://127.0.0.1:11434/v1", api_key="none")

async def update_long_horizon_memory(room_id: str, new_turns: list, prev_memory: str) -> str:
    """
    完全在本地 5090 运行，零云端 API 计费，零主会话 Prompt 指令开销。
    直接利用官方 CoMem 权重提炼'行动一致性'记忆块。
    """
    try:
        response = await comem_client.chat.completions.create(
            model="horizon-llm/CoMem-Qwen3-4B-ICML2026",
            messages=[
                {"role": "system", "content": "You are the CoMem decoupled memory manager. Extract sufficient statistics for agent action consistency."},
                {"role": "user", "content": f"Previous State:\n{prev_memory}\n\nRecent History:\n{json.dumps(new_turns)}"}
            ],
            temperature=0.1,
            max_tokens=2048,
            timeout=8.0  # 8 秒硬件超时闸门
        )
        return response.choices[0].message.content.strip()
    except Exception as e:
        # 服务未启动或异常时，平滑降级到 S1/S2 自述摘要拼装
        return build_fallback_summary(new_turns)
```

### I4: 直接接入 Aider RepoMap（`aider-chat`）

#### 解决痛点
手写 AST 提取和 PageRank 计算无法精准处理多语言（TS、Python、C#、Go）的复杂继承和动态调用，易造成代码地图失真。

#### 直接集成方案
在 Python 环境中直接安装官方 `aider-chat` 核心包，直接导入 `RepoMap` 类：
```bash
pip install aider-chat
```

#### 宿主胶水对接（`code_map.py` / `project_tools.py`）
仅需 10 行胶水代码完成成熟代码地图装配：

```python
# project_tools.py：直接引用 Aider 官方 RepoMap
from aider.repomap import RepoMap
from aider.io import InputOutput

def generate_repo_map(project_root: str, focus_files: list, budget_tokens: int = 2000) -> str:
    """
    直接调用 Aider 官方 RepoMap 算法。
    自动利用 tree-sitter 解析全语言语法树，
    并通过有向图 PageRank 算法自动根据当前 focus_files 计算符号重要性并精准截断。
    """
    io = InputOutput(yes=True)
    repo_map = RepoMap(root=project_root, io=io, verbose=False)
    
    # 直接由 Aider 输出高质量代码地图字符串
    map_content = repo_map.get_repo_map(
        chat_files=focus_files,
        other_files=[],
        max_map_tokens=budget_tokens
    )
    return map_content or "[代码地图为空或项目未初始化]"
```

# supervision.py
import toon

def format_ledger_payload(ledger_dict: dict) -> str:
    """
    直接使用 TOON 官方库序列化监工账本列表，
    比标准 JSON 节省 30%–50% Token，同时保证百分之百符合 TOON 标准解析规范。

### I7: 直接接入 ccusage 官方审计工具（`ryoppippi/ccusage`）

#### 解决痛点
各家服务商（Claude、OpenAI、DeepSeek）的 Token 计量与 Prompt Cache Hit 统计口径各异，手动计算极易因线程累计值错误而算错。

#### 直接集成方案
宿主通过 Node 执行环境直接调用官方 `ccusage` CLI，提取归一化 JSON 报表：
```python
# usage_report.py
import subprocess, json

def get_live_ccusage_report() -> dict:
    """
    直接调用 ccusage 官方工具。
    官方原生支持拆解 5 小时额度窗口、按会话累计差值和精准统计 Prompt Cache 读写比例。
    """
    result = subprocess.run(
        ["npx", "-y", "ccusage", "--json"],
        capture_output=True,
        text=True,
        shell=True
    )
    if result.returncode == 0:
        return json.loads(result.stdout)
    return {"error": "ccusage_execution_failed", "details": result.stderr}
```
