首选桌面“代理协作室”或 `http://127.0.0.1:49315`。完整说明见 本仓库 `README.md`。

用户定义自然语言合作规则，监工是独立会话身份，自选提供方与模型。团队成员可以增减、改名、分别选模型；支持 ChatGPT/Claude CLI、DeepSeek 官方 API 和自定义 OpenAI 兼容 API，同一服务可配置多位成员。监工使用所选成员连接但独立选模型。监工依据真实记录安排成员发言、并行独立提案、互相质疑或单方编码，并逐项检查和纠偏。ChatGPT、Claude、DeepSeek 只是初始成员；以当前配置名单为准，型号不是身份。不得预设某方必须规划、某方必须评审、某方必须执行。

GUI 可直接编辑规则，或在自由群聊中发给监工补充。运行中新规则在当前步骤结束后生效。直接从 CLI 使用时遵守同样原则；当前主控按用户合作方式协调，不声称存在没有实际调用的独立监工。需要完整多方可视过程时使用 GUI。

先读取适用 AGENTS.md/CLAUDE.md。可先用目录和 Git 摘要定位范围，小改动直接完成。需要编码时使用 task-contract 中的明确契约：目标、允许文件、验收命令和回传格式。必要项目规则、接口和上下文须写入契约；工作者不自动继承全部聊天。

MCP `codex_review`、`claude_review` 为可选的只读核对入口，支持 model 参数；省略则沿用 GUI 选择。DeepSeek 默认 flash 槽也沿用 GUI 选择，显式 pro 槽才使用配置中的升级型号。没有用户安排就不静默换模型。

DeepSeek 长任务使用 start_deepseek 保存 job_id，再用 status/message/cancel/result。静态阅读用 readonly API；命令、Git、测试用 coding。一个工作区同一时刻只有一个执行者。不要为了流程形式增加不必要的代理调用。

由主控核对实际变更范围和原有修改，必要时运行真正的验收，记录退出码。未运行测试须明确说明。写入或中断后读取 get_deepseek_recovery，核对文件 SHA 和范围，再传精确 transaction_ids 确认；Bash 变更另查 Git。命令过滤不等于 OS 沙箱。

缺登录、密钥、模型权限或余额如实记录；工具调用失败不能当作完成。监工检查引用实际记录，不展示私有推理。已有授权持续推进，提交、推送或发布依实际授权处理。
