使用方式与效果边界

这组设置控制“哪些材料在未来调用中以全文、摘要目录或输出预览呈现”。完整消息仍保存在宿主；模型需要细节时，可以在已有权限内分段回取。

  1. 先打开房间总开关，再选择具体功能；四个摘要使用场合还需要“作者自述摘要”开启。
  2. 编辑后点击“保存此协作室设置”。设置只影响当前房间，在下次调用时应用；优化配置改变后使用新上下文分支。
  3. 在“查看本房间用量与回取”中检查实际请求用量和回取情况。开关关闭后，已有原文和归档仍然保留。

已经进入原生会话历史的正文不会被追加摘要自动缩短。潜在收益主要发生在首次省略旧全文、新分支重建和大输出首次投递时；摘要生成、工具定义和回取本身也会消耗 token。

基础功能已做工程验收；真实模型的摘要忠实度、任务净费用和返工率仍待配对测试。九条实验路线均未开放，不能把开关名称当作已安装或已接入的能力。

可先阅读 总开关、作者自述摘要和用量口径。

输出预留 / API 输出上限

默认 32,768 · 本应用范围 1,024–128,000 · 当前房间保存后从下次请求生效

在哪里设置
打开“此协作室的上下文设置”，修改“输出预留 / API 输出上限”并保存。上下文软预算必须大于输出上限、安全余量与 1,024 tokens 输入空间之和。
功能与原理
API 讨论与编码执行均将此值传给实际请求的输出参数。在共享上下文窗口的模型中，该值也占用本地输入预算；CLI 的输出上限由原生运行器控制。
为什么会在 16,384 截断
0.14.0 及更早版本的编码适配器，把房间设置压到固定 16,384，MCP 配置与 HTTP 子进程也按这个旧值校验。0.14.1 已统一这三处传递和校验：例如设置 32,768，编码请求实际发送 max_tokens=32768。
包含哪些内容
输出计数可能同时包含推理、正文与工具调用参数。长思考或一次生成整份文件可能先用完额度，最终文本或工具参数随之截断。调高上限提供更多生成空间，不保证每个任务一定完成，也不会改变推理强度。
与服务商限制的关系
服务商限制仍独立生效。本应用目前允许最高 128,000；截至 2026-10-22，DeepSeek 官方文档允许 max_tokens 最高 393,216，不能据此推定其他兼容服务也支持相同上限。
失败后如何处理
输出截断进入宿主故障检查，保留文件、原错误和日志。“仅复查宿主”不调用模型，也不自动重新派发已启动契约。调整设置只影响后续请求，不恢复服务端已经截断的那次生成。

服务商原始参数定义见 DeepSeek Chat Completions：max_tokens 与 finish_reason。

每次发言的工具续轮上限

默认 16 · 范围 1–100 · 与输出 token 和监工协作轮数分别计算

功能与原理
限制一次发言或编码任务内“模型响应 → 工具执行 → 再次请求模型”的循环。一次响应可能包含多个工具调用；编码执行器的最后一轮如果仍在调用工具，轮数用完后就没有下一次模型总结，因而可能出现文件已写入但没有 STATUS: DONE 的情况。
如何调节
在同一上下文设置中修改“每次发言的工具续轮上限”。较长编码任务可能需要更多续轮；调高后最多请求次数、等待时间和 token 消耗也可能增加。调整此项不会扩大单次输出上限，也不会重新运行已经结束的任务。
失败后如何处理
轮数耗尽属于宿主运行故障。宿主核对文件、原契约验收与恢复记录，保留执行失败状态；不会为了获取一句成功总结再次调用执行者。存在待核实写入时保留记录并阻断重复派发。

启用此房间的上下文优化

默认关闭 · 仅当前房间 · 保存后从下次调用应用

功能
作为下方摘要、工具输出预览、只读项目工具及简洁指令的总开关。子选项即使已勾选，也需要总开关开启才生效。
原理
宿主在每次调用开始时读取房间配置。优化配置改变时建立新的上下文分支，避免把不同提示与投递策略混在同一原生会话中；正在进行的调用继续使用它开始时的设置。
开启或关闭后的行为
开启后按子选项构建未来请求；关闭后未来请求恢复原组包策略。原文、已生成的摘要和归档不会因此删除；已有归档指针仍可按原有权限回取。基础用量记录与报表继续可用。
适用场景与限制
适合需要比较不同组包方式的房间。切换分支可能需要重建上下文，也可能改变缓存条件；不能把一次请求 token 变少直接等同于整项任务省钱。

作者自述摘要

子选项默认勾选 · 需总开关开启 · 摘要由讨论成员在原回复中生成

功能
让较长的讨论回复附上“立场、要点、未决问题”，供监工和讨论成员定位旧消息，再按需读取原文。
原理
通过一段稳定指令，要求作者在同一次回复末尾写摘要。宿主严格解析格式，并把摘要与原消息的 SHA-256 哈希绑定；只在摘要和原文匹配时采用。表态行仍保留在最后。
摘要：立场=有条件｜要点=先保留日志再显示预览｜未决=中间错误需要回取核对

缺失、超长、格式错误、引用示例或代码块中的“摘要”不会被当作有效摘要。当前不会额外追问，也不会另调模型代写；历史中没有合格摘要的消息不会自动补齐。没有摘要时可回退原文或编号目录，具体取决于保护规则和预算。

摘要是导航，不能代替表态、批准或证据。用户原话、当前方案、相关未决异议和失败证据继续按保护规则保留原文；必要原文放不下时进入预算处理。执行者不参与群聊摘要投递，也不因本选项获得群聊工具。

四个使用场合可以独立控制。所有场合关闭后，本选项仍会请求作者生成摘要，并保留主动查询摘要目录的能力；如需停止生成摘要，应关闭本选项。摘要可能遗漏关键条件，实际忠实度和净收益仍需测试。

工具输出归档与有界预览

子选项默认勾选 · 需总开关开启 · 作用于已接入的宿主验收、Git 与执行器工具输出

功能
在大输出进入模型上下文前保存原始捕获文本，先展示有上限的首尾预览；需要中间内容时按输出编号分页回取。
原理
宿主在原有输出截断之前归档，记录输出 ID、文本哈希、所属房间与会话、命令、真实退出码和捕获完整标记。超过预览上限时，约三分之一剩余字符用于开头，三分之二用于末尾，中间显示省略及回取提示。
如何读取细节
模型通过 output_read 按字符偏移回取，每段最多 8,000 字符；你也可在“用量与回取”中打开归档，逐段查看。
限制
首尾预览可能漏掉中间的唯一错误，不能当作完整证据。运行器仍有捕获上限，例如 Bash 每个输出流最多 8,000,000 字节；超限会标记捕获不完整。归档是捕获并解码后的文本，不是无限保存的原始字节流。

退出码保持真实值，不因预览而把失败算作成功。回取按房间和角色核验；执行者只能读取同一执行身份的执行会话输出与宿主验收输出。关闭本功能会停止后续主动归档预览，既有归档仍可回取。

只读项目读取与搜索

子选项默认勾选 · 需总开关开启 · 提供给具备群聊工具权限的监工与讨论成员

功能
让成员在项目范围内按需读取文件和搜索文字，减少为了寻找少量信息而反复带入大段项目资料的需要。
原理
project_read 按行分页返回 UTF-8 文本；project_search 使用 Git 的已跟踪及未忽略文件清单进行字面搜索，返回文件路径、行号和命中片段。工具只读，不新增写文件或执行任意命令的能力。
返回预算
单次读取最多 400 行、12,000 字符；超过 2 MB 的文件或超长单行会被拒绝。搜索最多返回 100 处匹配，扫描有文件数和字节上限；未完成时会标记。搜索需要可用 Git 索引，已知路径的读取不依赖搜索。
限制
拒绝项目外路径、凭据及控制目录，例如 .env、密钥、.git、.codex、.claude。工具不提供二进制读取，也不等于 Aider RepoMap；现有项目快照仍保留。工具定义与调用结果也占上下文，实际是否减少总成本需要对照测量。

执行者继续使用原执行契约规定的工具与范围，本开关不会给执行者增加这些讨论工具。

简洁发言指令

默认不勾选 · 需总开关开启 · 作用于监工与讨论成员

功能
鼓励发言直接写结论、依据和需要别人做的事，减少客套、复述与重复总结。
原理
向角色提示中加入一条短指令，让模型在生成时主动控制表达。指令同时要求完整保留代码、命令和关键异议。
适用场景
适合长时间协作中重复解释较多的讨论；输出可能变短，后续带入历史的文本也可能随之减少。
限制
这是风格引导，模型未必每次遵守；不会硬截断已经生成的正文，不调整模型推理强度，也不改变执行者契约。需要长篇论证时可以关闭。输出质量和实际节省尚待真实模型验证。

监工较早发言

默认勾选 · 依赖总开关与作者自述摘要 · 仅监工“账本 + 新增原文”模式

功能
控制监工查看较早讨论材料时，是否优先使用已有的作者摘要。这里指“投递给监工的较早发言”，并非让监工给自己的历史补写摘要。
原理
组包时，把非关键、未投递且有合格摘要的旧讨论放入目录，保留原文 ID 供回取。监工刚要求成员回复的新材料、当前方案和受保护争议继续发原文。
关闭的影响
停止这个场合的优先摘要策略，改由原文候选与总预算决定投递。预算不足时，“未加载目录”等其他场合仍可能提供摘要。
限制
监工选择“完整状态 + 新增原文”时，本项不启用这条历史优先策略；不会重写已经进入监工原生会话的正文。

未加载目录

默认勾选 · 依赖总开关与作者自述摘要

功能
为本次未装入全文的消息提供作者摘要，帮助成员判断哪些原文值得继续读取。
原理
宿主先装入必须保留的原文，再将其他未装入消息放进有界目录。目录项包括 ID、序号、作者、哈希和可用摘要；空间不足时可退为仅编号，更多条目通过目录工具分页查看。
关闭的影响
这个场合的目录不主动附摘要，仍可保留编号和回取方式。“监工较早发言”或“新成员补看”主动选择的摘要不由本项关闭；四个场合各自控制其投递来源。
限制
目录不保证列出所有历史，也不说明模型已读全文。这里控制自动组包；成员主动调用摘要目录工具仍可查询已有摘要。部分回取只有在所有分段齐全后，才记为完整原文已投递。

分支交接

默认勾选 · 依赖总开关与作者自述摘要 · 新建上下文分支时使用

功能
在新分支的交接包中，补充更早消息的摘要目录，帮助新分支查找近期原文之外的背景。
原理
交接包包含宿主记录、配置数量内的近期原文及受保护材料；本选项额外为更早、未重复包含且有合格摘要的消息生成有界目录。目录本身也计入预算。
关闭的影响
交接包不追加这份更早摘要目录；原有交接账本、近期原文和原文归档仍保留。新分支后续的其他摘要投递仍由其他场合开关控制。
限制
交接包只是重建当前所需上下文，不等于复制全部历史。摘要不能替代批准记录或成功证据；必要细节仍须回取原文。

新成员补看

默认勾选 · 依赖总开关与作者自述摘要 · 讨论角色首次建立原生会话时使用

功能
让新加入的讨论成员先通过摘要了解较早背景，避免第一次发言就携带大量旧全文。
原理
在讨论成员尚未建立当前分支的原生会话时，把非关键、有作者摘要的旧消息优先放入目录。新分支中首次重建会话的老成员也属于这个条件。
关闭的影响
不使用这条优先摘要策略，改由原文候选和预算决定。若其他场合仍开启，未装入全文的消息依然可能在相应目录中出现摘要。
限制
用户要求、当前方案、相关未决异议等保护原文不因此降为摘要；也不会重复改写该成员已经收到的历史。

长回复阈值（字符）

默认 400 · 范围 0–5,000 · 依赖总开关与作者自述摘要

功能与原理
决定多长的讨论回复需要附作者摘要。宿主只有在整条回复字符数严格大于此值时才接受摘要；等于阈值也按短回复处理。
调节影响
调低会让更多回复需要摘要，增加摘要输出和目录开销；调高只覆盖较长发言，短消息继续用原文或编号表示。
限制
单位是程序统计的文本字符，包含空白和标点，不是中文词数或模型 token。改值只影响后续生成与解析，不会自动重算旧消息。

摘要上限（字符）

默认 160 · 范围 40–400 · 依赖总开关与作者自述摘要

功能与原理
限制整条摘要行长度，包含“摘要：立场=…”等固定格式和标点。宿主仅接受符合格式且不超限的摘要。
调节影响
较小的值减少每条目录占用，但更难保留条件和未决问题；较大值允许更多细节，也会更快耗尽目录预算。
超限怎么办
摘要超长会被拒绝，正文继续保存；不会裁掉摘要末尾，也不会发起补问。参数变更不重算已保存摘要。

目录最多条数

默认 30 · 范围 1–100 · 每次自动生成的目录页上限

功能与原理
限制一页摘要或编号目录的候选条数。宿主优先选择较新消息，并同时检查实际序列化后的预算；因此真正返回的条目可能少于此值。
调节影响
调大可以展示更多历史入口，也增加编号、哈希和摘要开销；调小使当前请求更轻，但可能需要额外翻页。
限制
不是历史保存条数，也不是所有目录的合计上限。主动调用 group_list_messages 的每次读取仍最多 30 条，交接目录还受自己的预算约束。较早消息仍可通过续页或已知 ID 回取。

目录预算比例

默认 0.15（15%） · 范围 0.05–0.5 · 控制预算上限，非固定分配

功能
限制自动摘要目录最多占用多少可用输入预算，防止摘要和编号本身挤满上下文。
原理
普通组包取“输入预算 × 本比例”和“扣除提示、安全余量及固定预留后的可用空间的三分之一”中较小的值。若整个请求仍超预算，目录会继续缩小。目录的完整 JSON、ID、哈希及续页信息全部计入。
调节影响
比例越大，可能容纳更多摘要，也可能挤压非关键原文空间；越小则更容易降为编号或需要翻页。0.15 不是强制用满 15%。
限制
交接目录另有更保守的预算上限；条数上限也会同时生效。此参数使用本地 token 估算，不是服务商最终账单；字符数与 token 数不能直接等同。

输出预览上限（字符）

默认 6,000 · 范围 1,000–50,000 · 依赖总开关与工具输出归档预览

功能与原理
限制单份归档输出首次呈现给模型的预览文本长度，省略提示和输出指针也占这个上限。短于上限的输出直接显示原文，仍会归档。
调节影响
调小减少首次投递量，却可能增加后续分页回取；调大保留更多现场信息，但大输出仍可能遗漏中间内容。
限制
不是归档容量上限，不改变运行器捕获边界，也不改变 output_read 单次最多 8,000 字符。回取的文本会进入后续模型请求，净收益要把它算进去。

详见工具输出归档与有界预览。

用量口径与回取记录

不依赖优化总开关 · 报表展示已有记录 · 查看归档会新增回取记录

功能
按成员、角色、会话分支、日期、适配器或发言类型查看用量，并查看最近 50 条归档输出及回取次数。日期按 Europe/London 划分。
原理与口径
服务商输入总量已经包含缓存读取与写入，输出总量已经包含推理子项；不能再把子项加一次。缓存命中率只对输入和缓存读取均已知的请求，计算“缓存读取合计 ÷ 输入合计”。
输入总量 1,000，其中缓存读取 800、缓存写入 100
输入仍为 1,000；这组已知数据的缓存命中率为 80%。

字段缺失保持“未知”；“另 N 次未知”表示部分请求没有该字段，显示的合计只覆盖已知记录。全文、摘要、仅编号是投递形式记录；回取一段不等于读取整篇，也不能证明模型理解或采纳了内容。

报表不会自动计算可信的任务净节省或订阅实际账单。比较优化效果需要同类任务配对运行，计入所有生成、工具续轮、回取、缓存和返工，并同时比较任务质量与延迟。
